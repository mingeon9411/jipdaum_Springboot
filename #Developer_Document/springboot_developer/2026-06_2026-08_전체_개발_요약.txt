
⭐ jipdaum_Springboot 전체 개발 요약 (2026-06-26 ~ 2026-08-23)

➡️ 프로젝트 초기 커밋, 결제 시스템 Spring Boot 통합 및 주문/쿠폰/상품 API 구현
➡️ 결제/인증 보안 취약점 수정 및 서비스 계층 정리


✅ 2단계 — 인증 시스템을 Django에서 Spring으로 포팅 (7/13 ~ 7/31)

➡️ Django Users 앱(회원가입/로그인/로그아웃/닉네임확인/이메일OTP)을 Spring으로 포팅,
   프론트엔드 계약(/api/users/*, 필드별 에러)에 맞춤
➡️ 소셜 로그인(카카오/네이버/구글) 안정화, 회원 탈퇴 기능, 탈퇴 계정 재로그인 시
   자동 복구 문제 수정, 네이버 계정 불일치/세션 재사용 버그 수정
➡️ OWASP 점검 후 인증/권한 취약점 보완
➡️ 인증 메일을 로고 포함 HTML 메일로 개편(J.D/한옥 브랜드별 분리)


✅ 3단계 — DB 전환 및 인프라 정리 (7/21 ~ 7/24)

➡️ Oracle → MySQL(Docker, jibdaum DB) 전환, Django와 스키마 공유(ddl-auto: none)
➡️ Hibernate 물리 네이밍 전략 고정(대문자 테이블명 매칭), 주문 추적 필드 자동 생성
➡️ 다른 PC 인수인계용 CLAUDE.md/application.yml.example 정리


✅ 4단계 — 관리자 기능 및 계층 정리 (8/3 ~ 8/7)

➡️ Docker CI/CD(Docker Hub 이미지 빌드/푸시) 최초 도입
➡️ 카테고리/쿠폰/상품옵션 관리자 CRUD API, 리뷰 이미지 업로드 지원
➡️ 컨트롤러 계층 위반 정리(Controller > Service > Repository)
➡️ 미인증 /api/** 요청에 302 리다이렉트 대신 JSON 401 반환하도록 수정


✅ 5단계 — Gemini 기반 AI 챗봇 도입 (8/16 ~ 8/21)

➡️ Gemini LLM 챗봇 도입(stateless 멀티턴 + 상품 조회 tool-calling)
➡️ Bucket4j로 IP/계정당 rate limit, 인테리어 컨설턴트 페르소나 프롬프트
➡️ RAG(임베딩 의미 검색) 도입 — 상품명에 없는 질의도 의미 기반으로 검색
➡️ 상품 진열(collection) 스코프 추가 — 메인/한국관 페이지별로 검색 범위 분리
➡️ Gemini 응답 파싱 버그(Content-Type 오응답) 수정, 도구 호출 라운드 축소로 응답 지연 개선
➡️ EC2 자동 배포 CI 스텝 추가(main push 시 Docker 빌드→EC2 배포)
➡️ hCaptcha 챗봇 게이트는 UX 문제로 추가 후 곧 제거, 소셜 로그인엔 유지


✅ 6단계 — 최근 세션: 보안 점검, 챗봇 상품 패널, PASS/hCaptcha 원복 (8/22 ~ 8/23)

➡️ 자체 보안 리뷰 — Gemini API 키가 URL 쿼리스트링에 있어 타임아웃 시 로그에
   평문 노출되던 문제 발견/수정(x-goog-api-key 헤더로 전환)
➡️ 챗봇이 search_products로 실제 찾은 상품 전체 목록을 응답에 실어 프론트 화면
   오른쪽 패널에 자동 표시하도록 개선(메인/한국관 공용)
➡️ 프론트가 hCaptcha를 PASS(통신사 본인인증) 데모로 교체하면서 백엔드 실검증과
   어긋나 회원가입/로그인이 막혔던 문제 발견 → 백엔드 검증 제거로 임시 대응 →
   이후 "다시 hCaptcha로" 요청에 따라 백엔드+프론트 전체 원복
