✅ 재고 차감 동시성 방어 로직에 부하 테스트 추가 (ProductOptionConcurrencyTest)

➡️ OrderService.verifyPayment이 쓰는 ProductOptionRepository.decrementStockIfAvailable
   (DB 레벨 조건부 UPDATE)이 실제 동시 요청에서도 재고를 음수로 안 만드는지 검증
➡️ 재고 5개 옵션에 20개 스레드를 CountDownLatch로 동시 출발시켜 각각 수량 1씩 차감 시도.
   스레드마다 TransactionTemplate으로 독립 트랜잭션 사용(테스트 메서드를 @Transactional로
   감싸면 한 트랜잭션 안 순차 실행이 되어 의미 없음)
➡️ 가드를 일부러 지우고 돌려 뮤테이션 테스트 수행 — 발견: stock_count 컬럼이 DB 스키마상
   BIGINT UNSIGNED라 가드 없이도 음수가 되는 순간 MySQL이 자체 에러를 던져 최종 재고 수치는
   우연히 똑같이 나옴(이중 안전장치 존재). 다만 이 경우 앱은 조용한 "재고 0"이 아니라 SQL
   예외로 죽어 같은 트랜잭션의 결제 완료 처리까지 롤백될 위험이 있음
➡️ 그래서 테스트에 exceptionCount 검증도 추가 — 가드 제거 시 실제로 테스트가 실패하는 것까지
   확인(AssertionFailedError: expected 0)한 뒤 가드 원상복구, 최종 34개 테스트 전부 통과
